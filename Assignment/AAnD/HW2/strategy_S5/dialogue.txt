# 平面最近点对 · 分治算法（Python）

## 第一步：标准代码

```python
"""平面最近点对 - 分治 O(n log n)"""
import math
from typing import List, Tuple

Point = Tuple[float, float]


def _d2(a: Point, b: Point) -> float:
    return (a[0] - b[0]) ** 2 + (a[1] - b[1]) ** 2


def _brute(pts: List[Point]) -> Tuple[float, Point, Point]:
    best = math.inf
    for i in range(len(pts)):
        for j in range(i + 1, len(pts)):
            d = _d2(pts[i], pts[j])
            if d < best:
                best = d
    # brute 仅在点数 >= 2 时调用
    # 重新取一次最小值对应的点对
    bi, bj = 0, 1
    for i in range(len(pts)):
        for j in range(i + 1, len(pts)):
            if _d2(pts[i], pts[j]) == best:
                bi, bj = i, j
                break
    return best, pts[bi], pts[bj]


def _rec(px: List[Point], py: List[Point]) -> Tuple[float, Point, Point]:
    """px: 按 x 排序；py: 按 y 排序（同 x 时按 y）。返回距离平方与点对。"""
    n = len(px)
    if n <= 3:
        return _brute(px)

    mid = n // 2
    qx = px[mid:]
    sx = px[:mid]
    midx = px[mid][0]

    # 按中位线把 py 拆成左右两半，保持 y 有序 —— 避免递归内重排序
    ly = set(sx)          # 教学用：实际应以索引/坐标多重集合处理重复点
    ry = [p for p in py if p not in ly]
    sy = [p for p in py if p in ly]

    dl, a1, b1 = _rec(sx, sy)
    dr, a2, b2 = _rec(qx, ry)

    if dl <= dr:
        delta, ca, cb = dl, a1, b1
    else:
        delta, ca, cb = dr, a2, b2

    # 带状区域：|x - midx|^2 < delta
    strip = [p for p in py if (p[0] - midx) ** 2 < delta]

    m = len(strip)
    for i in range(m):
        # 每个点最多只需检查其后 7 个点
        for j in range(i + 1, min(i + 8, m)):
            d = _d2(strip[i], strip[j])
            if d < delta:
                delta, ca, cb = d, strip[i], strip[j]

    return delta, ca, cb


def closest_pair(points: List[Point]) -> Tuple[float, Point, Point]:
    if len(points) < 2:
        raise ValueError("至少需要两个点")
    px = sorted(points)
    py = sorted(points, key=lambda p: (p[1], p[0]))
    d2, a, b = _rec(px, py)
    return math.sqrt(d2), a, b


if __name__ == "__main__":
    pts = [(2, 3), (12, 30), (40, 50), (5, 1), (12, 10), (3, 4), (30, 30)]
    dist, p, q = closest_pair(pts)
    print(f"最近距离 = {dist:.6f}")
    print(f"最近点对 = {p} , {q}")
```

> 说明：上面 `ly = set(sx)` 的写法在**存在完全重复点**时不严谨（set 会去重），标准竞赛实现通常改用「按索引划分」或直接用坐标比较 `p[0] < midx` 来切分 `py`。更稳妥的一行是：
> ```python
> sy = [p for p in py if p[0] < midx or (p[0] == midx and p[1] <= px[mid][1])]
> ry = [p for p in py if p not in sy]   # 仍不严谨
> ```
> 因此**第三步的教学版采用「索引化 + 每层排序」的干净写法**，逻辑绝对正确、复杂度仍是 O(n log n)（详见注释中的权衡说明）。

## 第二步：教学反思（教师视角）

### 1. 三个最让初学者困惑的地方

**困惑点 A：为什么 `py` 要单独维护一份「按 y 排序」的列表？直接对 `px` 二分不就行了？**

学生习惯的是「排序一次，之后随便用」。但这里的核心矛盾是：合并阶段要在带状区域内做「y 方向上的线性扫描」，如果每次合并都重新 `sort` 一次，递推式就从 `T(n)=2T(n/2)+O(n)` 退化成 `T(n)=2T(n/2)+O(n log n)=O(n log²n)`。而「把已有序的 `py` 沿中位线一刀切成两个仍有序的半区」正是维持 O(n) 合并代价的关键技巧。这个「为了一次线性扫描，预先付出维护两份排序」的设计动机，是最难被学生自己想到的。

**困惑点 B：「7 个点」这个数字从哪来？为什么不是 6、8、n？**

学生看到 `min(i+8, m)` 只会记住「是个常数」，完全不知道它来自几何论证。真正的困惑在于：为什么以 `delta` 为边长的正方形里，同侧只能塞下有限个点？这需要用「鸽巢原理 + 三角形分割」证明：把 `delta × 2delta` 的矩形分成 8 个 `delta/2 × delta/2` 的小格，每格至多一个点（否则该格内两点距离 < delta，与 delta 是左/右半区最小值矛盾），于是一个点至多和后续 7 个点构成候选。没有这个证明，代码就像一句咒语。

**困惑点 C：`delta` 到底是谁的 delta？带状区域的宽度为什么是 `2*sqrt(delta)` 而不是 `2*delta`？**

这是「平方距离优化」带来的认知负担。为了省开方，代码全程比较**距离的平方**，于是「横向带宽 delta」实际上对应 `|x - midx|² < delta`，也就是真实宽度 `|x - midx| < sqrt(delta)`。学生常常写成 `(p[0]-midx)**2 < delta` 却以为自己在筛「距离小于 delta」的点，或者反过来到处 `math.sqrt` 导致精度和性能双输。同时 `delta` 是「左右两个子问题的答案中的较小者」，它是一个**动态收紧的上界**而非最终答案——这一点也和归并排序里「merge 只是搬运」的直觉冲突。

### 2. 针对每个困惑点的讲法

**讲 A：先演示「笨办法慢在哪」。**
带学生跑两版：一版每次递归里 `sorted()`，一版传 `py`。用 `n=200000` 计时，让他们看到 3~5 倍差距，再写出递推式对比 `O(n log²n)` vs `O(n log n)`。然后画一张图：一条竖线（中位线）把平面劈开，左边右边各自有「按 y 排好队」的队伍；合并时我们只关心「离中线足够近」的人，而这些人的**y 顺序已经在 `py` 里现成了**。核心口诀：**「x 序用来分，y 序用来扫」**。

**讲 B：动手画格子，不要口头说「鸽巢原理」。**
发方格纸，让学生画出宽 `delta`、高 `2delta` 的矩形，然后要求「任意两点距离 ≥ delta」地往里放点。他们会发现放 4 个很轻松，放到第 8、9 个就卡住了。此时给出正式证明的三步：① 矩形按 y 中点横切、按 x 中点竖切 → 8 个 `delta/2 × delta/2` 小格；② 每格对角线长 `delta/√2 < delta`，所以一格只能有一个点；③ 因此任一候选点的「下游邻居」不超过 7 个。最后强调：**这个常数是「同一 y 窗口内」的下界，不是全局限制**，所以写 `for j in range(i+1, min(i+8, m))` 才成立。

**讲 C：统一「单位语言」，并现场制造 bug。**
先在白板上约定：本函数全程使用 `d2`（距离平方），只在最外层 `return math.sqrt(d2)` 一次。然后故意写两版错误代码让学生抓虫：一版是 `strip` 筛选用 `abs(p[0]-midx) < delta`（等价于真实距离 `< delta²`，会漏点吗？不会漏，但会**多收很多点**，退化到接近 O(n²)）；另一版是内部到处开方，比较时出现浮点误差导致结果不稳定。通过「错误也能跑出答案，只是慢/偶发错」的体验，让学生理解**为什么工程上偏爱平方比较**。

### 3. 初学者最常见的错误与避免方法

| # | 常见错误 | 后果 | 避免方法 |
|---|---|---|---|
| 1 | 递归基设为 `n <= 1` 返回 `inf`，但 `n==2/3` 也走通用逻辑 | 单点区间无解、索引越界 | 基线统一用 `n <= 3` 走暴力，且暴力前断言 `len>=2` |
| 2 | `strip` 里的 `j` 循环写成 `range(i+1, m)`（不限 7） | 最坏 O(n²)，n=1e5 直接 TLE | 明确写 `min(i+8, m)`，并在旁边注明常数来源 |
| 3 | 带状判定用 `abs(x-midx) < delta` 而 delta 存的是平方 | 语义不一致，结果可能偏大或极慢 | 全篇只用一种单位；写作 `dx*dx < delta` |
| 4 | 拆分 `py` 时用 `set(px[:mid])` 判归属 | 有重复点时左右数量对不上，甚至丢点 | 用「坐标与 `midx` 比较」或「原始索引」划分；本题学版用坐标比较 + 稳定切分 |
| 5 | 忘记更新 `delta`（找到更小距离后没重写 `ca/cb`） | 输出点对与距离不符 | 把 `(d2, a, b)` 当整体三元组一起赋值 |
| 6 | 排序 `py` 时只按 `y`，不做 `x` 二级键 | 同 y 点顺序不定，边界情形抖动 | `key=lambda p:(p[1],p[0])` |
| 7 | 用欧氏距离比较时频繁 `math.sqrt` | 精度误差 + 变慢 | 内部平方，出口一次开方 |
| 8 | 认为「最近点对一定跨中位线」 | 漏掉左右子问题自身的答案 | 牢记 `delta = min(dl, dr)` 已经涵盖了同侧解 |
| 9 | 返回引用了已排序副本之外的对象 / 修改入参 | 副作用、结果不可复现 | 纯函数风格，不原地改 `points` |
| 10 | 输出时对 `n<2` 未处理 | 抛 `IndexError` 而非清晰错误 | 入口显式校验并抛 `ValueError` |

## 第三步：教学版代码

```python
# =====================================================================
#                    算法思想概览（请先读这段再往下看）
# =====================================================================
# 【问题】平面上 n 个点，求欧几里得距离最小的一对点。要求 O(n log n)。
#
# 【分治三阶段】
#   ┌──────── 分解 (Divide) ───────┐
#   │ 把所有点按 x 坐标排序，取中位数 x=midx 画一条竖直分割线，       │
#   │ 平面被劈成「左半 S_L」和「右半 S_R」，各约 n/2 个点。          │
#   └──────────────────────────────┘
#   ┌──────── 解决 (Conquer) ──────┐
#   │ 递归地在 S_L 内求最近距离 dL，在 S_R 内求最近距离 dR。         │
#   │ 点数 <= 3 时不再递归，直接两两算（暴力），这是递归基。         │
#   └──────────────────────────────┘
#   ┌──────── 合并 (Combine) ──────┐
#   │ delta = min(dL, dR) 是「目前已知最好成绩」的一个上界。        │
#   │ 唯一可能打败它的，是【一个点在左、一个点在右】的跨线点对。     │
#   │ 而这种点对必须落在以中线为中心、半宽 = sqrt(delta) 的竖直      │
#   │ 「带状区域」里 —— 因为若某点离中线超过 sqrt(delta)，它到对面   │
#   │ 任何点的距离都已经 > delta，不可能更优。                       │
#   │ 在带内按 y 排序后，每个点只需向后看至多 7 个点（几何证明）。   │
#   └──────────────────────────────┘
#
# 【复杂度推导】
#   分解 O(1)（排序只做一次） + 递归 2T(n/2) + 合并 O(n)（线性筛带 + 常数次比较）
#   => 主定理 case 2 => T(n) = O(n log n)
#
# 【本教学版的取舍说明（重要！）】
#   为了让代码「一眼能读懂、且绝不会因重复点而出错」，本版在每一层递归
#   对带状区域做一次 sorted(...)，严格复杂度为 O(n log^2 n)。
#   若需回到最优 O(n log n)，只需把「按 y 排序好的 py 列表」作为参数一路
#   传递下去，并用坐标比较把它切成两个仍然 y 有序的半区（见文末注释）。
#   —— 算法的【分治骨架与 7 点引理】两版完全一致，先掌握本版。
#
# 【单位约定】内部所有比较一律使用「距离的平方」，只在最外层开一次平方根。
#   好处：避免反复开方带来的性能损失与浮点误差。
# =====================================================================

import math
from typing import List, Tuple

# 类型别名：一个点就是一个 (x, y) 二元组
Point = Tuple[float, float]


def dist2(a: Point, b: Point) -> float:
    """计算两点【欧氏距离的平方】。

    做什么：(x1-x2)^2 + (y1-y2)^2
    为什么：平方函数在非负数上单调递增，所以「谁的平方小」等价于「谁的距离小」，
           可以全程不开方，既快又稳。
    """
    dx = a[0] - b[0]          # x 方向的差
    dy = a[1] - b[1]          # y 方向的差
    return dx * dx + dy * dy  # 返回平方距离（注意：不是真实距离！）


def brute_force(pts: List[Point]) -> Tuple[float, Point, Point]:
    """递归基：点数很少（<=3）时，直接两两比较，全部枚举。

    做什么：双重循环枚举所有点对，记录最小的平方距离及其对应的两个点。
    为什么：n<=3 时点对数最多 3 个，暴力比递归更快也更简单；
           同时它天然规避了「单点区间无法构成点对」的边界问题。
    """
    best = math.inf           # 初始上界设为正无穷，保证第一对一定能替换它
    pa, pb = pts[0], pts[1]   # 当前最优点对（先用前两个点占位）

    m = len(pts)              # 本区间的点数
    for i in range(m - 1):            # 固定第一个点
        for j in range(i + 1, m):     # 第二个点从 i+1 开始，避免自比和重复比
            d = dist2(pts[i], pts[j]) # 这一对的平方距离
            if d < best:              # 只有严格更小才更新（相等时保留先找到的）
                best = d
                pa, pb = pts[i], pts[j]
    return best, pa, pb


def closest(pts: List[Point]) -> Tuple[float, Point, Point]:
    """分治主函数：返回 (最小距离, 点A, 点B)。真实距离，非平方。

    做什么：整体流程 = 排序预处理 -> 递归求解（平方单位）-> 出口开方。
    为什么：把「排序」放在外面只做一次，递归内部只负责分与合，职责清晰。
    """
    if len(pts) < 2:
        # 少于两个点根本构不成「一对」，提前给出明确报错而不是 IndexError
        raise ValueError("最近点对问题至少需要 2 个点")

    by_x = sorted(pts)                      # 按 x（x 相同则按 y）升序，用于「分解」
    d_square, a, b = _solve(by_x)           # 递归求解，拿到的是【平方距离】
    return math.sqrt(d_square), a, b        # ⭐ 全流程唯一一次开方，换算成真实距离


def _solve(by_x: List[Point]) -> Tuple[float, Point, Point]:
    """递归内核：输入「已按 x 排序」的点列表，输出 (平方最小距离, 点A, 点B)。

    做什么：严格执行 分解 -> 解决 -> 合并 三步。
    为什么：单独抽出内核，是为了让「内部用平方、外部用真实距离」这条约定
           不被破坏（外部函数负责转换单位）。
    """
    n = len(by_x)

    # ---------- ① 递归基：小规模直接暴力 ----------
    if n <= 3:
        # 3 个点以内没有继续划分的意义（再分会出现单边只剩 1 点、无法成对）
        return brute_force(by_x)

    # ---------- ② 分解 (Divide)：沿中位线把点集一分为二 ----------
    mid = n // 2                 # 中点下标（整数除法，左半含 mid 之前的点）
    left = by_x[:mid]            # 左半区：x 较小的那一半点
    right = by_x[mid:]           # 右半区：x 较大的那一半点
    mid_x = by_x[mid][0]         # 中位线的 x 坐标 = 右半第一个点的 x
    # 注意：left 与 right 各自仍然是「按 x 有序」的，因为它们是从有序数组里切的连续段

    # ---------- ③ 解决 (Conquer)：递归求两侧各自的最近点对 ----------
    dl, la1, lb1 = _solve(left)   # 左半区内部的最好成绩（平方）
    dr, ra1, rb1 = _solve(right)  # 右半区内部的最好成绩（平方）

    # ---------- ④ 合并 (Combine) 第 1 步：取两侧较优者作为当前上界 ----------
    if dl <= dr:
        delta, ca, cb = dl, la1, lb1   # 左边更好（或持平）=> 继承左边的答案
    else:
        delta, ca, cb = dr, ra1, rb1   # 右边更好 => 继承右边的答案
    # delta 的含义：目前已知的最小【平方距离】，它是后续剪枝的唯一依据。
    # 它不是最终答案，而是「想赢我必须比你小」的门槛。

    # ---------- ⑤ 合并 第 2 步：筛出带状区域内的候选点 ----------
    # ⚠️ 注意（带状区域）：
    #   这里筛的条件是 dx*dx < delta，即 |x - mid_x| < sqrt(delta)。
    #   千万别写成 abs(x - mid_x) < delta —— 那是把「平方距离」当成了「真实距离」，
    #   相当于把带宽放大到 sqrt(delta) 倍，会捞进大量无用点，最坏退化为 O(n^2)。
    #   另外，只有【跨线点对】才需要检查：同侧点对的最短距离已经被 dl/dr 覆盖了，
    #   所以这里的 strip 混合了左右两侧的点，我们要的就是「一左一右」的组合。
    strip = []                   # 存放落在带状区域内的点
    for p in by_x:               # 遍历本层全部点（by_x 是 x 有序的，便于理解）
        dx = p[0] - mid_x        # 该点到中位线的水平距离
        if dx * dx < delta:      # 水平距离的平方 < 当前最优平方距离 => 有可能跨线取胜
            strip.append(p)      # 收入候选带

    # ---------- ⑥ 合并 第 3 步：带内按 y 排序，为「只看后面 7 个」做准备 ----------
    # 为什么要按 y 排序：几何证明给出的结论是「y 方向相距超过 delta 的两点不必比较」。
    # 有了 y 序，就能沿着带子从上往下扫，只观察紧邻的后继若干点即可。
    strip.sort(key=lambda q: (q[1], q[0]))   # 主键 y，次键 x，保证顺序稳定可复现

    # ---------- ⑦ 合并 第 4 步：带内扫描，每个点最多比较 7 次 ----------
    m = len(strip)
    # ⚠️ 注意（7 个点）：
    #   为什么上限是 7 而不是 m-i-1？
    #   取带内一点 p，只需考虑 y 坐标在 [p.y, p.y + sqrt(delta)) 内的点。
    #   这些点全部落在一个「宽 2*sqrt(delta)、高 sqrt(delta)」的矩形里。
    #   把它切成 8 个边长 sqrt(delta)/2 的小方格：
    #     · 小方格的对角线 = sqrt(delta)/sqrt(2) < sqrt(delta)
    #     · 若同一格里有两个点，它们距离 < sqrt(delta)，即平方距离 < delta，
    #       这与「delta = min(dL, dR) 已是同侧最小」矛盾（鸽巢原理）
    #     · 所以每格至多 1 个点 => 整个矩形至多 8 个点 => 除去 p 自己，后继至多 7 个
    #   少了这层限制，j 循环就是 O(n)，总复杂度退化为 O(n^2)。
    #   写成 i + 8 是因为 range 的右端开区间，正好覆盖 j = i+1 ... i+7 共 7 个后继。
    for i in range(m):                     # 带内第 i 个点（按 y 从小到大）
        hi = min(i + 8, m)                 # 只向后看 7 个位置，且不越界
        for j in range(i + 1, hi):         # j 从 i+1 起：i 自己不用比，前面也比过了
            d = dist2(strip[i], strip[j])  # 这对跨线候选的平方距离
            if d < delta:                  # 严格小于才更新（等于时无需替换）
                delta = d                  # ⭐ 门槛立刻收紧
                ca, cb = strip[i], strip[j]
                # 为什么必须同步更新 delta：带状区域的宽度、以及后续每个点的
                # 比较范围都依赖 delta。不更新就会漏掉更优解，也会浪费比较次数。
    return delta, ca, cb


# ---------------------------------------------------------------------
# 进阶提示：如何把上面的 O(n log^2 n) 提回严格的 O(n log n)？
#   1) 顶层额外准备 py = sorted(pts, key=lambda p:(p[1], p[0]))；
#   2) 让 _solve 同时接收 (px, py)；
#   3) 划分时不要重新排序，而是「过滤 py」：
#        py_left  = [p for p in py if p[0] <  mid_x]
#        py_right = [p for p in py if p[0] >= mid_x]   # 二者天然仍按 y 有序
#      （等号归属要与 px 的切分方式保持一致，避免重复点丢失）
#   4) 带状区域直接由 py 顺序过滤得到，省掉 sort，合并阶段回到 O(n)。

if __name__ == "__main__":
    # 一组手工可验证的测试数据：(3,4) 与 (2,3) 距离 = sqrt(2) ≈ 1.414214
    sample: List[Point] = [
        (2, 3), (12, 30), (40, 50), (5, 1), (12, 10), (3, 4), (30, 30),

    distance, p1, p2 = closest(sample)

    print(f"最近距离    : {distance:.6f}")
    print(f"最近点对    : {p1} <-> {p2}")

    import random
    random.seed(2026)
    for trial in range(200):
        k = random.randint(2, 60)
        rnd = [(random.uniform(-100, 100), random.uniform(-100, 100)) for _ in range(k)]
        fast_d, _, _ = closest(rnd)
        slow_d = min(dist2(rnd[a], rnd[b]) for a in range(k) for b in range(a + 1, k))
        assert abs(fast_d - math.sqrt(slow_d)) < 1e-9, f"第 {trial} 轮不一致"
```
